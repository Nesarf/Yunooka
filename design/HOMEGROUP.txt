Yunooka 的家庭组
================

一、Windows 的家庭组是什么

它是 Windows 7 加进来的东西，Windows 10 1803 又拿掉了。拆开来看是五个部件：

  发现      同一局域网里的机器自动看见彼此，不填地址、不记 IP
  边界      一个「家庭组密码」。加入时要输入它，输对了才算家里的人
  共享      文件夹、打印机、媒体库。选一个目录说「共享出去」
  权限      给家里的人读，或者读加写。对「不是家里的人」一律不给
  身份      谁在共享、谁在访问，用用户名认

它当年难用，原因很具体：发现靠一串协议叠在一起（SSDP、WS-Discovery、LLMNR），
而这些东西一旦碰上防火墙、IPv6、或者网络里多一台路由器，就一半能用一半不能。
「网络发现了另一台机器但共享打不开」是它最常见的症状。

二、Yunooka 现在没有的东西

这一台机器没有网卡 —— 网卡是关着的（nic1=none），而且就算打开也没有网络栈：
没有 ARP、没有 IP、没有 UDP 或 TCP。上面那五个部件里，「发现」与「身份」两件
完全依赖网络，第三、四件依赖前两件。

所以「照搬」这件事不成立：照搬的第一步就得先写一整个网络栈，而那东西本身并不是
家庭组 —— 它只是家庭组的运输层。运输层做好之后，家庭组仍然一行都没开始。

更麻烦的是「多台机器」：这台机器现在连两个程序同时跑都做不到。家庭组的意义是
「另一台机器看得见我的东西」，而没有第二台，这一层无从验证。

三、魔改成什么

先回答一个问题：家庭组最要紧的那一层是什么。

是「边界」与「共享」这两件 —— 把某样东西标记成「愿意给家里的人看」，并且有一个
可信的判据说「这台机器是不是家里的人」。发现只是省了输地址，身份只是让共享有个
主人，而这两件都可以晚。

所以 Yunooka 的家庭组这样改：

  边界   是盘上的一个数，不是一串密码。超块里加一个「家」ID（u32）。
         两块盘上的家 ID 相同，它们就是一家人。
  共享   是目录条目上的一个标记位，不是一张单独的共享表。
         一个目录被标记成共享，它就在共享清单里。
  发现   没有发现。盘在手里，你就知道它是哪一块 —— 这一层在 Yunooka 上
         没有可省的动作，所以不做。
  身份   暂时没有。这台机器只有一个执行流，没有「谁」。
  权限   只有一档：看得见 = 读得到。分档要等有身份。

于是「跨机器」在 Yunooka 上的样子是：把盘递过去。一块 β 盘拔下来、插到另一台
Yunooka 上，两边的家 ID 一样，那边就看得见这边共享的目录。

这不是妥协，是这台机器现在唯一能真的做到的形态。它也有一个好处：它把「信任边界」
做成了一个可以检查的数，而原来的家庭组把它做成了一段可以和别人说的密码 —— 后者
在没有网络身份的地方没法验证。

四、为什么不先做网络

网络栈是运输层。先做运输层再做家庭组，等于先修路再决定运什么。

而且运输层一旦开始，就会吞掉很多东西：ARP 的缓存、IP 的校验和、UDP 的端口表、
重传、分片。那些东西都要判据，而它们的判据与「家庭组」没有任何关系。

真正挡住家庭组的不是运输层，是「这台机器上没有第二台、也没有第二个程序」。所以
正确的下一步不是网络，是把「共享」与「边界」做成盘上的事实 —— 它们不需要网络就能
被验证，而且网络来了之后它们仍然是对的。

五、第一步：共享标记与列出

最小可判的一步，不碰网络也不碰第二台机器：

  一个目录的条目上有一个「共享」位。加上、去掉、列出来。
  判据是三条：标记之后清单里有它、清单里能看出它的类型（目录还是文件）、
  再标记一次同一路径不会出现两遍。

这三条各自会坏，而坏的样子不同：清单只按名字对会漏掉「同一个目录被标记两次」；
只按位置对会把改过名的当成新的。

六、还没定的

家 ID 什么时候写、由谁写。两个家 ID 不同的盘插在一起时，是被拒绝还是被当成
另一台机器的盘（能看见但不共享）。权限分档（只读与可写）要不要跟着「身份」一起等。
共享的目录被删掉时，清单里那条算什么。

这四件都等第五步做完，因为它们的答案取决于「共享」这个动作最后是什么形状。
