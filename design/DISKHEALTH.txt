盘的健康：三条路，与一条被修正的结论
====================================

目标是把 CrystalDiskInfo 那一套做成 Yunooka 的。它读的是 SMART，而 SMART 的命令跟着
控制器走：IDE 与 SATA 是 ATA 的 0xB0 一族，NVMe 是 Log Page 0x02。所以「读不到」这句话
在三条路上是三件不同的事，得分开说。

IDE：IDENTIFY DEVICE 一页零
----------------------------

已排除四条，都在「自己这边」那一侧：DEV 位（0xA0 与 0xE0 都试过）、DRDY（等 bit 6
起来再送）、400ns 延迟（读 0x3F6 四次近似）、缓冲区（512 字节、清零过，而读扇区用
同一类缓冲是好的）。

还有一条实测事实把 DEV 那条钉死：VBoxManage showvminfo 里 disk.vdi 挂在 IDE port 0
device 0，也就是 primary master，而 0x1F6 的 0xE0 正是它。所以那个位没写错。

结论：那块盘不答这一条命令。剩下的条件只有换控制器。

AHCI：六个 port 的 PxSSTS 全零
-------------------------------

细节在 design/AHCI.txt。一句话：在两个芯片组上都判死了，而 BIOS 通过同一个控制器访问
过盘 —— 也就是说控制器是通的，只是固件这一侧没走到能读盘的那一步。

NVMe：命令成功，而数据没进来
----------------------------

这一条是这一轮才看清的，而它修正了一条旧结论。

旧记录写的是：Get Log Page 也跑通了（status 是 0，命令成功），而 VBox 的 NVMe 返回的
那一页全是零 —— 它没有真的温度与寿命可报。

这一次把那条命令重新写回去（它连同读法一起被拿掉过，所以那个结论一直没有代码支撑），
并且把完成项的 status 单独打出来。串口上是：

    Yunooka: nvme smstat 0
    Yunooka: nvme smart EE80EE805642313233342D353637383920202020202020204F52434C2D56424F

status 是零，命令成功。而那一串十六进制解出来是 VB1234-56789 与 ORCL-VBO…… —— 也就是
Identify Controller 那一页的内容。这条命令按时完成了，而它**没有写缓冲区**，里面还是
上一条命令留下的东西。

所以旧结论「返回一页零」只对了一半：当时缓冲区是清零的，看起来就是零。真相是「命令被
接受，而数据没进来」。

这两个的区别不是措辞。前者说「盘给了零值」，那会让人去查「为什么是零」；后者说「这一页
在模拟里没实现」，那直接给出「此路不通」。一个把结论写错一半的记录，比没有记录更费人：
它会让人在一条已经走不通的路上再走一遍。

顺带一句读法上的事：NUMD 是「要几个 dword，减一」，而这一页是 512 字节 = 128 个 dword，
所以 CDW10 里那个字段该是 127。写小了不会报错，只会让盘少写几个字节 —— 剩下的就是缓冲
区里原本的零，而症状与「盘不报」一模一样。这一轮的实现里它是 127。

为什么它值一条判据
------------------

判据要求三行都在且 status 是零。那证明命令发了、也被接受了 —— 而「发了并被接受」是这个
环境里能拿到的全部肯定的东西。

至于内容是真数据还是旧数据，判据不做，因为它没法做：两种形状在串口上都合法。但它把事实
留在串口上 —— 那一串里嵌着型号与序列号，而一块真的报 SMART 的盘会给出温度、通电时间、
一串不相干的计数，形状完全不同。

一个准确的「我不知道」比一个假的零度好。这一条在这里尤其要紧，因为「温度 0」会被下游
当成一个可用的数。

还能做什么
----------

在 VBox 这一层到此为止：三条路都试过，而 NVMe 那条是「命令被接受但没实现」。

往外走有三条，按代价排：

一、换 QEMU。它的 NVMe 实现报了 SMART log，而 tools/run.mjs 现在是 VirtualBox 专用的。
    这是最直接的一步，但把整条测试链换掉不是小事。

二、换真机。最彻底，也最不可重复。

三、接受现状，把「健康」这一层做成「能读到什么就报什么」：型号、序列号、容量都能读到
    （NVMe 那两条 Identify），温度与寿命报「这一层读不到」。CrystalDiskInfo 的价值有
    一半在「它把哪些数当成健康指标」这一层判断上，而那一层不必等 SMART 真的可用 ——
    它可以先写好，等数据来。

第三条是这一层现在能做的，前两条要等环境变。
