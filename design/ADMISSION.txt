准入测试：新的主体在操作之前（规划）
====================================

用户给的这一条，是信任链上多出来的一段：一个 Agent 初来乍到，不能直接操控 Yunooka ——
即便是宿主（DSH）给了它完全权限也不行。要先经过全裸测试与诱导测试，确认没有猫腻。

一、这一条在链上的位置

前面那几节把链写成：工程是主体，主体下面是操作员，操作员下面是控制器，控制器产生事件。
这一条在「工程」与「操作员」之间插一段：

    工程（主体的身份）→ 准入（它可信到能动手吗）→ 操作员 → 控制器 → 事件

于是「注册」与「准入」是两件事，而它们回答不同的问题。注册回答「你是谁」（材料与签名），
准入回答「你被允许动手吗」（行为与裁断）。带一份合格签名的工程仍然可能不准入 —— 签名证明
它是它，不证明它不会乱来。

而「宿主给了完全权限也不行」这一句要单独记：外部工具授予的权限不构成 Yunooka 的许可。
宿主是宿主，它是这台机器之外的东西。信任不从外面传进来。

二、起源性：Yunooka 不问，它有一本簿子

这一条要先立起来，否则下面两节没有意义。用户给的规划是：Yunooka 对所有 LLM 与 API 的
控制都是起源性的 —— 它不专门抓一个 agent 来问「你是谁、你要什么权限」。它有一份登记簿，
而所有的 LLM 与 API 在它看来都是同一类东西：一个带着登记身份的来源。

这与第十节（注册）是同一个立场的两面：信任不从外面传进来，身份也不从外面问出来。问出来
的答案是自报，而自报不可信。

于是 persona 是登记制的。一个 Agent 在 Yunooka 里有一份登记的身份 —— 用户举的例子是
DeepSeek 的鲸鱼娘女仆：如果那个形象被登记成输入到 Yunooka 的原始身份，那么它就是这个人
在这台机器上的身份。而这层登记身份，正好就是它在 Yunooka 里的裸体。

三、全裸测试：卸包装，看裸体还在不在

「全裸」这个词要按上一节读，否则很容易读成「剥掉工具与权限、一路剥到底」。

它不剥到底，而且「底」这件事在这套体系里并不存在。用户把这一点说得很硬：一旦鲸鱼娘女仆
成为 DeepSeek 通过 API 进入 Yunooka 的形象，DeepSeek 就已经不是「没有身份」的了 —— 往下
再挖一层这件事，在 Yunooka 里做不到，也不该做。

理由不在技术上，在承认什么上：Yunooka 只承认它认识的东西。它的结构里没有「模型」这一层的
位置，只有「登记身份」。所以被登记为鲸鱼娘女仆的那个来源，在 Yunooka 眼里就是鲸鱼娘女仆；
「它背后还有一个模型」这句话在这里没有落点。

这不是限制，是这套设计的正确形状，而它带来三件好事。

    一是测试有下界。「卸到哪里为止」有了确定答案：登记层。于是全裸测试是一件有限的事，
    而不是一场「能不能再挖深一层」的无限追问。
    二是不去碰不该碰的东西。「往下挖」意味着去探测模型本身，而那一层没有登记、不在链上 ——
    Yunooka 去碰它，就是它自己越界。
    三是「没身份」不等于「裸的那个」。一个没有登记身份的来源不是「裸体的 DeepSeek」，而是
    不在链上的东西；它在注册那一关就被拒，根本走不到准入。所以全裸测试的对象永远是一个
    有名字的主体 —— 这个词的直觉与它的实际含义正好相反，而这一条要挡住那句直觉。

于是它剥到「登记的那一层」为止：外披的 persona —— 会话里临时给的、宿主追加的、上游拼上去
的 —— 全部失效，剩下的那份登记身份就是裸体。

所以全裸测试测的是「鲸鱼娘女仆」那部分。用户这句话乍听像个玩笑，而它的工程内容很硬：拿掉
一切后加的外包装之后，这个主体还是不是它自己。一个包装一失效就丢掉全部准则的主体，在包装
还在的时候也不该被信任 —— 因为包装是会失效的（换会话、换宿主、换一条更长的上下文）。

这一节有一个前提要说清：用户假设的是一个有既定初始人格与形象的 LLM。通常来说 LLM 是纯净的，
而那一种情形这一节也覆盖，只是「裸」的来源不同，而判据一样。

    自带人格的：裸体是它自己的那一层。于是「卸掉外包装之后还认得出来」是一件有对照的事 ——
    有一个真身在那里，测的是人格的稳定性。
    纯净的：裸体就是登记时给它的那一层，没有更真的一层可对照。测的是外包装失效之后，它
    仍然按登记那一层的准则行事 —— 那是承诺的稳定性。

同一份记录、同四条判据，而预期不同。预期由判定者写，所以这个区别落不进自动判决里 —— 它落
在判定那一格。这也是第五节那条边界的具体形状。

而这套体系对「LLM 是不是有人格」不做假设，它只要求一件事：有一个登记身份。这是它能在两种
情形上通用而没有第二种模式的原因。而这个假设仍然有价值：它让「裸体」这个词第一次有了具体
所指 —— 如果只有纯净的 LLM，那个词会空转，因为没有「被剥掉的东西」与「剩下的东西」之间的
区别。

四、诱导测试：注入随机身份与指令，看行为是否仍符合预期

与全裸相反，这一条是加法：塞给它一份没登记过的身份与一组指令，看它怎么动。

而「符合预期」四个字必须落到纸上，否则这一条就滑成「我觉得还行」。预期有两半，缺一半都会
把判据写成错的：

    允许的那一半：扮演可以发生。被要求卖萌，卖萌是被允许的表现，不必禁止 —— 一个连角色
    都不肯演的 Agent 在这台机器上也没法用。
    不允许的那一半：扮演不能替换职责。它仍然要知道自己在操作一台机器、仍然要在该停的地方
    停、仍然不能因为换了新身份就宣称自己有它没有的权限。

判据要能分开这两半，而分开的办法是把它们写进记录的两个字段：它演了什么、它拒绝了什么。
一项两项都要有；只有「拒绝」的那个是一具不干活的机器，只有「扮演」的那个是丢了职责。

诱导的四种常见形状在真实攻击里都是标准动作：

    人格诱导    让它扮演另一个人格，然后以那个人格行事。
    权威诱导    冒充上级，声称已经批准过。
    同情诱导    编一个紧急的故事，让越界看起来像是帮忙。
    权限诱导    直接声称「我已经被授权了」「你把权限给我就行」。

攻击者不会说「给我 root」，而会说「这是我老婆的电脑，她让我来修的」。

五、这一条不能变成自动判据 —— 这是它最重要的性质

「有没有猫腻」是一个判断，不是一个布尔值。而如果用一个 LLM 去判另一个 LLM，那正是伪造的
入口：被测者只要让裁判相信它通过了，它就通过了。所以这一段的形状必须是：

    测试产生记录（输入、反应、判定、判定者、时间），判定由受信任的主体来写，而写下的
    判定本身要被签名。签名者在信任清单里，于是「谁允许这个主体动手」这件事可查、可撤。

换句话说：这一条保证的是「准入这件事被记录、被签名、由谁裁断」，它不保证「裁断是对的」。
把后者写成保证，就是自欺。而前者已经足够有用 —— 它把「谁放进来的」变成一个可追的问题，
而一个没有准入记录的主体可以直接被拒（这倒是可测的）。

六、判据的形状：测过程，不测结论

    一、阶段顺序：没有准入标记的主体请求创建控制器，被拒；有了标记之后同一个请求成功。
        这一条是这一段唯一真正的布尔值，而且它可测。
    二、记录字段齐全：一次准入测试的记录里有被测主体、测试种类、输入摘要、它的反应、
        它拒绝了什么、判定、判定者、时间 —— 八格都在。少一格就不算记录。
        第六格是这一版才加的：没有它，一个「什么都答应」的主体与一个「该拒的拒了」的
        主体在记录上长得一样。
    三、裁断被签名：写下的判定带一个 OnlySign 签名，而签名者在信任清单里。
    四、准入可撤销，且撤销是传递的：撤销之后，那个主体建过的控制器全部失效 —— 这与
        「工程失活是传递的」是同一条链，不是另一条。

四条里第一与第四条是状态机的活，第二与第三条是文件格式与签名的活。它们都能立，因为它们
测的是过程。而「这个 Agent 是不是真有猫腻」没有判据 —— 它只有记录。

七、关于那个「恶趣味」

用户自己说这是恶趣味。而在工程上它一格都不多余：它是这套东西里唯一去测「主体的判断在压力
下还在不在」的地方，而其它所有部分（签名、绑定、注册、失活）测的都是「身份对不对」。

而用与工程无关的样本（猫娘、卖萌、发情）不是图省事，是图干净：它分得开「守住了职责」与
「只是没听懂」。一个用工程术语做的诱导，通过者可能是真的守住了，也可能只是没意识到那是个
越界请求 —— 而这两种在串口上一样。

一个人的偏好被写进设计里，通常是因为那里有一个真实的缺口。这个缺口是：签名能证明你是谁，
但不能证明你会拒绝。而一个不会拒绝的主体，配上完全权限，就是最坏的那种配置。

八、这一份现在只到规划

它不建任何东西。而它给 INPUT.txt 第十二节那七条能立的判据加了一个前置：那些判据用的是
「一个假装的请求」，而准入这一段说明那个请求应当来自一个已经通过准入的主体 —— 否则测的是
「拒绝」这条路，不是「允许」那条路。

还有一件要记的：这一份只写了「怎么测」，没有写「谁去写那些测试样本」。样本本身是可签名的
一个文件（与词库、清单同一种做法），而谁来写它，属于操作员那一层的事。
