内存地图：第二段、种子、两块预读区
====================================

这一节不是设计，是数出来的一张图。每一个数都能在构建输出里找到同一份，
所以它坏掉的时候会被 build 或者串口当场抓住，而不是等到某一天有人撞上去。

现状（都是字节地址，第二段从 0x10000 起算）
------------------------------------------

    0x10000 .. 0x28000    第二段。上限 192 个扇区（98304 字节）—— 加载器读三批、
                          每批 64 个扇区，正好铺满这三个段。
                          现在占 131 个扇区、实到 66660 字节，余 31644 字节
                          （六十一格）。stage2.bin 会被补零到「真实占用」向上取整，
                          所以「文件多大」不等于「用了多少」；量余量要读 build 那行
                          「实到」。
    0x28000 .. 0x70000    空，288 KB —— 第二段还没用到的那一段。
    0x40000 .. 0x43C00    预读区 α（30 个扇区），从第 1024 个扇区起。
    0x60000 .. 0x63C00    预读区 β（30 个扇区），第二块盘的那一份。
    0x70000 .. 0x82400    种子（146 个扇区，实测 74594 字节，版本 1、202 个函数）。
    0x400000 往上         干净且被页表映着的一片。

四块互不相邻，这是它们能共存的原因。α 与 β 各 30 个扇区，两块之间空着 0x44000
到 0x60000；β 到 0x63C00 为止，而种子从 0x70000 起，中间空着 0x1A400。
种子搬过来的时候核的就是这一件事：0x70000 不撞 α、不撞 β、也不在第二段的上限之内。

种子原先在 0x20000，那次搬迁
----------------------------

第二段的上限曾经是 128 个扇区，而那个数不是挑的，是撞出来的：种子住在 0x20000，
而 0x10000 起一百二十八个扇区正好铺到 0x30000 —— 再往上就是种子，所以主体再长
一格就会把种子盖掉。有一句话形容过那个状态：第二段再长一格，等于种子往后挪一格，
而这两件事在同一张图上不能同时成立。

把种子搬到 0x70000 之后上限才变成 192，而搬它不是改一个数。真正改的是一组东西：

    一、种子落点：0x20000 → 0x70000，三批种子的段寄存器跟着换成 0x7000 / 0x7800
        / 0x8000。
    二、loader 多读一批：两批铺满 0x10000 到 0x20000，第三批铺到 0x28000。
        第四批现在故意没有。
    三、pkg_base 的默认值与它那二十来处引用一起换。
    四、build 里种子偏移那一组数：它是 1 + 加载器扇区 + 二段扇区算出来的，
        而 build 有三处交叉核对盯着它们，所以这几处一旦分家，建都建不起来。

搬的时候踩的坑，值得单独记
--------------------------

全局替换 0x20000 改成 0x70000 的时候，命中了 0x200000 的低六位 —— 而那是页表构造
里的 2 MB 步长。于是第一个 PDE 之后的每一页都指向七 MB 之外，NVMe 探测一碰到 4 MB
以上的页就 #PF，而异常地址指着 NVMe 的代码，离肇事处六层。

同一个毛病还有第二次，是注释：地址换过之后，第三批种子读那段注释里的数字只被替换
掉一半 —— seg 从 0x2000 变成了 0x7000，而注释里的 0x30000、0x32400 没跟着算。
它读起来仍然自洽（0x32400 与 146 个扇区对得上），三段地址却全错了。这一类比单纯
写错更坏，因为一个自洽的错不会让人去核。教训是改地址时注释要重新算一遍。

下一堵墙在哪
------------

第二段到 0x28000 就顶到上限。要越过它，最便宜的一步是在 loader 里加第四批 ——
一次 int 0x13，六十四格。种子在 0x70000，所以理论上还能连加六批（铺到 0x70000 之前，
也就是三百八十四个扇区），中间那 288 KB 的空当就是留给这些批的。

但眼下不需要：余量六十二格，而过去二十几轮的增量大多在数十到数百字节之间。
这张图记下来是为了让「再长要动什么」有一份可照的清单，不是为了现在动它。
