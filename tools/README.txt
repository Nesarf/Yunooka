tools 下的脚本：谁在链上，谁是尺子，谁已经走了
==============================================

留下来且在链上的
----------------

build.mjs      编两段、拼盘、转 vdi。盘上每一份文件的布局都从这里来。
run.mjs        挂盘、引导、读串口、比对。所有判据都住在它里面。

留下来当尺子的
--------------

ed25519.mjs    Ed25519 的纯函数实现。build.mjs 用它签名，refed25519.mjs 用它跑向量。
refed25519.mjs 它的命令行外壳：RFC 8032 三条向量、自造长消息向量、逐层中间量。
refsha512.mjs  SHA-512 的参考实现，能算每一次压缩之后的 h。多块缺陷就是靠它查出来的。
genconst.mjs   算 SHA-512 的 80 个常量。stage2.asm 里 sha512_k 的注释指着它。
audit.mjs      仓库自检：判据有没有挂在链上、PLAN 的依赖能不能解析、design 是不是纯文本。
               它验的不是机器，是我们写下来的东西有没有自相矛盾。第一次跑就抓出十三个
               design 文件里八十八处 markdown 加粗 —— 那些是这二十几轮里我自己写进去的。

已经走了的
----------

这一轮删掉八个。它们各自都完成了任务，而任务完成之后只剩下两个作用：让人以为还有更多
的入口，以及在某一天被误当成判据跑一遍。

checksha512.mjs   六行对拍。它的逻辑已经并进 run.mjs。而在并进去之前，它读的是
                  build/serial.log —— 那个文件 run.mjs 早就不写了。也就是说那条判据
                  与主链脱节了很久，却一直挂在那里像还活着。
diagsha512.mjs    扫长度找第一个与 crypto 不符的。多块缺陷查清之后没有用途。
sha512words.mjs   第二份独立实现（64 位拆两个 32 位）。交叉验证用，缺陷修好之后没有用途。
shbit.mjs         逐位实现。同上，而且它证明了错处不在「位对齐」那一侧。
trypad2.mjs       把 112 字节补齐的每一种猜法试一遍。结论已经落在 design/SHA512.txt。
sha384probe.mjs   用 SHA-384 的初值跑同一套压缩。它证明的是「错不在初值」，结论已记。
try-pipe.mjs      试一次 pipe 通道。虚拟机那一侧的结论已经落在 README 里。
try-tcp.mjs       试一次 tcpserver。同上。

都还在 git 历史里。要找某一天的某一次诊断，用 git log --follow 去找它。

一条留下来的经验
----------------

诊断脚本的寿命比它解决的问题长得多。解决之后它有两种命运：被并进判据，或者被删掉。
留在原地是第三种，而那是唯一会骗人的一种 —— 它看起来还能跑，而它跑出来的东西不再被
任何人检查。

手动跑的判据不算判据。它不在任何一次通过的路径上，所以它红不红没人知道。checksha512
就是这样：它曾经是对的，而它读的那个文件早就不存在了。
